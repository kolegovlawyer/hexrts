# Инструкция по использованию профайлера Godot Editor для отслеживания лагов

## 🎯 Цель
Найти узкие места в производительности игры SimpleRTS и оптимизировать их.

## 📊 Встроенный профайлер Godot

### 1. Запуск профайлера
1. **Откройте проект** в Godot Editor
2. **Запустите игру** (F5 или кнопка Play)
3. **Откройте профайлер**: `Debug` → `Profiler` или `Ctrl+Shift+P`

### 2. Основные вкладки профайлера

#### 🔥 **CPU Usage** - Основная вкладка
- **Показывает**: Время выполнения функций в миллисекундах
- **Сортировка**: По времени выполнения (самые медленные сверху)
- **Колонки**:
  - `Function`: Имя функции
  - `Calls`: Количество вызовов
  - `Self`: Время выполнения самой функции (без подфункций)
  - `Total`: Общее время (включая подфункции)
  - `Average`: Среднее время выполнения

#### 🎮 **Frame Time** - Время кадров
- **Показывает**: График времени выполнения каждого кадра
- **Красная линия**: 16.67ms (60 FPS)
- **Желтая линия**: 33.33ms (30 FPS)
- **Пики выше красной линии** = лаги

#### 🧠 **Memory** - Использование памяти
- **Показывает**: Выделение и освобождение памяти
- **Проблемы**: Утечки памяти, избыточные аллокации

### 3. Как использовать для поиска лагов

#### Шаг 1: Запустите игру с ботами
```bash
# В консоли Godot:
# 1. Запустите сервер
# 2. Добавьте 2-3 ботов через Server UI
# 3. Подключите клиента
# 4. Дождитесь активной игры (50+ юнитов)
```

#### Шаг 2: Анализ CPU Usage
1. **Откройте вкладку CPU Usage**
2. **Ищите функции с высоким Total time**:
   - `_physics_process` - основной цикл
   - `_process_heavy_server_calculations` - тяжелые вычисления
   - `_get_visible_enemies` - поиск врагов
   - `can_see_target` - проверка видимости
   - `attack` - система атак

#### Шаг 3: Анализ Frame Time
1. **Откройте вкладку Frame Time**
2. **Ищите пики** выше красной линии (16.67ms)
3. **Кликните на пик** - увидите детали того кадра

#### Шаг 4: Детальный анализ функций
1. **Кликните на функцию** в CPU Usage
2. **Изучите Call Stack** - какие функции вызывают проблемную
3. **Обратите внимание на**:
   - Большое количество вызовов (`Calls`)
   - Высокое среднее время (`Average`)
   - Высокое общее время (`Total`)

## 🔍 Специфичные проблемы SimpleRTS

### Проблема 1: Перегрузка _physics_process
**Симптомы**: Высокое время выполнения `_physics_process`
**Причины**:
- Слишком много юнитов обрабатывается каждый кадр
- Тяжелые вычисления в основном цикле
- Отсутствие FrameGroup оптимизации

**Решение**:
```gdscript
# В base_unit_server.gd добавлено профилирование:
func _physics_process(delta: float) -> void:
    _profile_function_start("_physics_process")
    # ... код ...
    _profile_function_end("_physics_process")
```

### Проблема 2: Медленный поиск врагов
**Симптомы**: Высокое время `_get_visible_enemies`
**Причины**:
- Поиск по всем юнитам каждый кадр
- Отсутствие кэширования
- Неэффективные алгоритмы

**Решение**:
```gdscript
# Добавлено кэширование и профилирование:
func _get_visible_enemies() -> Array[BaseUnitServer]:
    _profile_function_start("_get_visible_enemies")
    # Кэш на 5 фреймов
    if cached_result_is_fresh():
        return cached_result
    # ... вычисления ...
    _profile_function_end("_get_visible_enemies")
```

### Проблема 3: Избыточные сетевые операции
**Симптомы**: Высокое время RPC функций
**Причины**:
- Слишком частые синхронизации
- Неоптимизированные RPC вызовы
- Избыточная передача данных

## 📈 Встроенная система профилирования

### Использование в коде
```gdscript
# В base_unit_server.gd добавлены функции:
func _profile_function_start(function_name: String) -> void
func _profile_function_end(function_name: String) -> void
func get_profile_stats() -> Dictionary
func log_profile_stats() -> void
```

### Получение статистики
```gdscript
# В консоли Godot (Debug → Remote Debug):
# Выберите юнит в дереве сцены
# В консоли выполните:
unit.log_profile_stats()
```

## 🎯 Практические советы

### 1. Тестирование производительности
- **Запускайте с 100+ юнитов** для выявления проблем
- **Используйте ботов** для создания нагрузки
- **Тестируйте разные сценарии**: бой, движение, захват гексов

### 2. Интерпретация результатов
- **Self time > 1ms** - функция требует оптимизации
- **Calls > 1000** - возможно избыточные вызовы
- **Total time > 5ms** - критическая функция

### 3. Оптимизация по приоритету
1. **Функции с высоким Total time** (самые критичные)
2. **Функции с высоким Self time** (прямая оптимизация)
3. **Функции с большим количеством Calls** (алгоритмическая оптимизация)

### 4. Мониторинг в реальном времени
- **Используйте Frame Time график** для отслеживания лагов
- **Следите за пиками** во время интенсивных действий
- **Сравнивайте до/после** оптимизаций

## 🚨 Частые проблемы и решения

### Проблема: Игра лагает при большом количестве юнитов
**Диагностика**: Высокое время `_physics_process` в CPU Usage
**Решение**: 
- Проверить FrameGroup систему
- Оптимизировать тяжелые вычисления
- Добавить кэширование

### Проблема: Лаги при атаках
**Диагностика**: Высокое время функций `attack`, `can_see_target`
**Решение**:
- Оптимизировать поиск целей
- Добавить кэширование видимости
- Уменьшить частоту проверок

### Проблема: Лаги при движении юнитов
**Диагностика**: Высокое время навигационных функций
**Решение**:
- Оптимизировать NavigationAgent2D
- Уменьшить частоту пересчета путей
- Использовать упрощенные алгоритмы для ботов

1. **Запускайте профайлер** при тестировании
2. **Анализируйте CPU Usage** для поиска узких мест
3. **Используйте Frame Time** для отслеживания лагов
